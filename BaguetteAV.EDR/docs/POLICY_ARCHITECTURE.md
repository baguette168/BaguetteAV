# B-EDR 自定义防护策略架构

最小接入示例见 [策略扩展开发指南](策略扩展开发指南.md)。

## 1. 设计目标

B-EDR 的策略系统不是“换一个告警名字的演示面板”，而是一条完整的本地研究链路：

```text
真实遥测 -> 样本导出 -> 策略编写 -> 离线演练 -> 回归测试
        -> 静态校验 -> 覆盖报告 -> 原子导入 -> 后台热加载
        -> 实时命中 -> 告警/响应 -> 版本回滚
```

目标是把新木马行为快速沉淀为可复用策略，同时保持四个约束：

1. 单机部署：后台保护服务与 WPF 控制台在同一台 Windows 上运行。
2. 默认不可执行：导入的 JSON 只能表达声明式条件，不能运行命令或脚本。
3. 可验证：导入前必须能对真实样本做离线演练和校验。
4. 可恢复：任何策略都能停用、回滚或删除历史版本。

## 2. 组件边界

| 组件 | 职责 | 安全边界 |
|---|---|---|
| `BaguetteAV.EDR.Service.exe` | 持有检测引擎、规则状态、响应能力 | LocalSystem 后台服务，开机自启，失败自动恢复 |
| `BaguetteAV.EDR.exe` | 图形化控制台、告警展示、策略操作 | 管理员进程，通过本机命名管道控制服务 |
| `BaguetteAV.EDR.Core` | 遥测、规则、策略、响应、持久化 | 不依赖 UI，可单元测试 |
| `BaguetteAV.EDR.PolicyTool` | 校验、演练、回归测试、覆盖、安装、回滚 | 研究命令行入口 |
| 策略 JSON | 声明式检测条件与受限响应动作 | 不能执行任意代码 |
| 代码插件 DLL | 需要复杂状态机时的扩展点 | 必须登记 SHA256，默认拒绝加载 |

控制管道为 `\\.\pipe\BEDR.Local.Control`，默认 ACL 仅允许 LocalSystem 和本机管理员。它不是远程管理协议，也不接受跨主机策略下发。

## 3. 策略数据模型

策略包顶层字段包括 `schemaVersion`、`id`、`name`、`version`、`author`、`description`、`minEngineVersion`、`tags` 和 `rules`。每条规则包含：

- 标识：`id`、`name`、`description`、`mitre`
- 评分：`severity`、`score`
- 适用事件：`eventKinds`
- 条件树：`condition`
- 响应请求：`response`
- 研究标签与引用：`tags`、`references`

条件树支持：

- 组合：`all`、`any`、`not`
- 字符串：`eq`、`ne`、`contains`、`startsWith`、`endsWith`、`regex`
- 集合：`in`、`notIn`
- 数值：`gt`、`gte`、`lt`、`lte`
- 存在性：`exists`、`missing`
- 自定义遥测：`field.<name>`

字段覆盖进程、父进程、网络、文件、驱动、WMI、LSASS 访问和远程线程。例如：

```json
{
  "all": [
    { "field": "driver.userwritable", "op": "eq", "value": "true" },
    { "field": "driver.signed", "op": "eq", "value": "false" },
    { "field": "process.image", "op": "regex", "value": "(?i)users\\\\.*\\.exe$" }
  ]
}
```

## 4. 导入与信任链

导入流程在后台服务或策略工具中执行：

1. 文件大小不得超过 2 MB。
2. JSON 反序列化失败直接拒绝。
3. 校验 schema 版本、ID/版本格式、事件类型、操作符、字段和值类型；未知字段直接拒绝，扩展字段必须写成 `field.<name>`。
4. 检查规则 ID 是否与内置规则或其他已安装策略冲突；冲突包整体拒绝，避免部分规则静默失效。
5. 校验条件深度不超过 10、节点不超过 256、规则不超过 512。
6. 预编译正则，单次匹配超时 100 ms，避免灾难性回溯阻塞检测线程。
7. 校验 `minEngineVersion`，拒绝高于当前引擎版本的策略。
8. 同一策略 ID/版本已存在时只接受相同 SHA256 的幂等导入；内容变化必须提升版本号，保证审计记录可追溯。
9. 计算 SHA256 并写入版本元数据；写入前确认数据目录仅 `SYSTEM` 与 `Administrators` 可写，加固失败时拒绝外部策略和插件（fail-closed）。
10. 先写临时文件，再原子替换 `policy.json` 和 `meta.json`。
11. 更新 `state.json` 的活动版本；服务监视策略仓库，450 ms 防抖后自动热加载，GUI/CLI 安装走同一条路径。
12. 每次热加载重新核对活动版本、包 ID 和文件 SHA256；不匹配时拒绝该策略并保留其他规则。
13. 导入、启停、回滚和删除操作追加写入 `audit.jsonl`，记录时间、动作、策略 ID、版本、SHA256 和操作者。变更前预检审计文件可追加；审计目标不可写时拒绝操作（fail-closed）。

同一个策略包可保留多个版本。导入新版本时旧版本自动成为 `Previous`，回滚只切换活动指针，不重新下载网络内容。

SHA256 是安装完整性标记，不是发布者身份签名。管理员权限被攻陷时，攻击者可以同时改写策略和元数据；策略目录 ACL、服务账户权限、Windows 审计和发布包签名属于更高层信任基础。B-EDR 在服务启动和导入前把数据目录 ACL 收紧为仅 `SYSTEM` 与 `Administrators` 可写；如果当前进程无权完成加固，则禁用外部策略与插件加载，而不是继续从可被普通用户写入的目录加载内容。

## 5. 响应动作

策略可声明以下响应请求：

| `response` | 行为 |
|---|---|
| `inherit` | 沿用全局响应设置 |
| `alert` | 仅记录告警 |
| `terminate_process` | 终止命中进程 |
| `quarantine_file` | 隔离命中文件 |
| `block_destination` | 阻断告警中的远端地址 |
| `contain` | 终止、隔离并阻断 |

响应请求不是无条件执行。全局响应模式仍必须是“自动处置”；受保护进程、系统目录和引擎自身不会被策略绕过。策略不能声明 shell 命令、脚本、URL 或任意文件删除路径。

## 6. 代码插件

当声明式规则无法表达复杂状态机时，可在独立 .NET 程序集中实现 `IEdrPlugin`，提供策略包或 `DetectionRule`。插件加载要求：

1. DLL 位于插件目录。
2. `trusted.json` 中存在同名文件。
3. 当前文件 SHA256 与登记值完全一致。
4. 插件 ID 不重复，策略包通过同一套校验器。

未登记、哈希变化或加载异常都只产生错误记录，不影响内置规则运行。

## 7. 研究工作流

| 阶段 | 操作 | 产出 |
|---|---|---|
| 采集 | 开启实时防护，产生真实进程/网络/驱动事件 | 内存中的最近 512 个遥测样本 |
| 固化 | GUI 导出遥测，或手工整理事件样本 | `*.events.json` |
| 编写 | 写规则、字段、阈值、响应动作 | `*.policy.json` |
| 演练 | GUI“离线演练”或 `bedr-policy simulate` | 样本数、命中次数、命中详情 |
| 校验 | `validate` 或导入前自动校验 | 错误/警告列表 |
| 部署 | GUI 导入或 `install` | 带 SHA256 的版本目录 |
| 运营 | 观察告警、标记误报、调阈值 | 新版本或误报记录 |
| 回退 | GUI 回滚或 `rollback` | 上一活动版本 |

离线演练不启动进程、不修改系统、不执行响应，只复用生产条件求值器，因此演练结果与线上规则语义一致。

### 7.1 策略回归测试

回归测试文件 `*.tests.json` 把正样本、负样本和预期命中规则固化为可重复验收用例。执行 `bedr-policy test <policy> <tests>` 或 GUI“运行回归测试”：

- `expect`：必须命中的规则 ID；
- `forbid`：不得命中的规则 ID；
- `strict`：出现未声明命中即失败，适合负样本误报回归；
- 未知规则 ID 直接判失败，防止规则改名后测试静默失效。

### 7.2 策略覆盖报告

`bedr-policy coverage` 聚合活动策略包的规则数、启用数、ATT&CK 技术、遥测事件类型、严重级别、响应动作、未标注规则和跨包重复规则 ID。`--markdown` 输出可直接放入论文或研究记录的表格；GUI“导出覆盖报告”使用同一分析器。

### 7.3 可加装能力分层

| 层级 | 扩展方式 | 适用能力 | 生效方式 |
|---|---|---|---|
| L1 | 本地设置 | 监控开关、自动处置、IOC、端口 | 保存后应用 |
| L2 | JSON 策略包 | 进程/网络/文件/驱动/WMI/LSASS/远程线程复合条件 | 热加载 |
| L3 | 遥测样本 | 真实事件回放、误报和回归测试 | 只读 |
| L4 | 受信任插件 DLL | 时间窗、状态机、跨事件关联、专有解析器 | 服务重载 |

主程序不执行导入脚本。复杂逻辑只能通过 L4 插件进入，插件失败会隔离为加载错误，不影响内置规则。

## 8. 与普通消费级杀软的区别

| 能力 | 普通消费级 AV | B-EDR |
|---|---|---|
| 规则入口 | 开关、白名单、少量 HIPS | JSON 策略包、字段级复合条件 |
| 关联判断 | 固定产品逻辑 | `all/any/not` 组合与评分 |
| 研究样本 | 通常不提供导出 | 实时遥测导出为可复现样本 |
| 上线前验证 | 依赖厂商云端 | 本地离线演练、命中详情 |
| 版本管理 | 不透明 | SHA256、版本目录、活动指针、回滚 |
| 响应 | 厂商预设 | 策略可请求受限动作，全局开关兜底 |
| 扩展 | 不可编程 | 受信任代码插件 |
| 边界表达 | 营销口径 | 明确用户态不可覆盖的内核篡改范围 |

### 8.1 内核马研究链覆盖

| 攻击阶段 | 观测字段 | 研究环境响应 |
|---|---|---|
| 驱动投放 | `file.path` 为 `.sys` 且 `file.userwritable=true` | 告警、隔离样本 |
| 持久化 | `parent.image`、`process.commandline`、WMI 过滤器/消费者字段 | 告警、终止可疑进程 |
| 漏洞驱动加载 | `driver.userwritable=true`、`driver.signed=false` | 告警、关联驱动路径 |
| C2 外联 | `network.destination.port` 为 8443/31337 | 告警、阻断远端地址 |
| 凭据访问 | `target.image=lsass.exe` 与 `target.access` 掩码 | 告警、终止请求 |
| 远程注入 | `target.image` 为浏览器/LSASS、`RemoteThread` 事件 | 告警、终止请求 |

驱动加载后的内核内存篡改仍需 HVCI、WDAC、漏洞驱动阻止列表和 hypervisor 监控补充；用户态策略不能把这类威胁宣称为已完全阻断。

## 9. 适用场景与边界

适用于：内核马投放链研究、WMI 持久化、漏洞驱动加载、C2 端口外联、LSASS 访问、远程线程注入、策略回归测试和毕业设计实验。

不适用于：绕过真实目标授权、远程批量控制他人主机、替代内核级完整性保护。用户态 API 无法可靠恢复已完成的 LSTAR/MSR 写入或 DKOM 全链表摘除；这类威胁必须在驱动加载前由 HVCI、WDAC、漏洞驱动阻止列表和更高级监控拦截。
