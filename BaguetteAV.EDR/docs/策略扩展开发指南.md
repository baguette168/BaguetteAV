# B-EDR 策略扩展开发指南

本文给出把一个新的木马行为接入 B-EDR 的最小闭环。先写声明式策略；只有时间窗、跨事件状态机或专有解析器才需要代码插件。

## 1. 最小策略包

```json
{
  "schemaVersion": 1,
  "id": "research.example.c2",
  "name": "研究环境 C2 外联",
  "version": "1.0.0",
  "author": "lab",
  "description": "用户可写目录进程连接 8443",
  "minEngineVersion": "2.0.0",
  "tags": ["c2", "research"],
  "rules": [
    {
      "id": "RESEARCH-C2-8443",
      "name": "8443 C2 外联",
      "description": "用户可写目录进程连接研究 C2 端口",
      "mitre": "T1071",
      "severity": "Critical",
      "score": 30,
      "response": "alert",
      "eventKinds": ["NetworkConnect"],
      "condition": {
        "all": [
          { "field": "network.destination.port", "op": "eq", "value": 8443 },
          { "field": "process.userwritable", "op": "eq", "value": "true" }
        ]
      }
    }
  ]
}
```

字段 `response` 先设为 `alert`。确认误报后，再改为 `contain` 或 `block_destination` 并递增 `version`，不要直接覆盖线上版本。

## 2. 条件字段速查

| 研究对象 | 常用字段 |
|---|---|
| 进程 | `process.image`、`process.path`、`process.commandline`、`process.sha256`、`process.signed`、`process.userwritable`、`process.signer` |
| 父进程 | `parent.image`、`parent.path`、`parent.pid` |
| 网络 | `network.destination.ip`、`network.destination.port`、`network.destination.host`、`network.protocol` |
| 文件 | `file.path`、`file.effective`、`file.userwritable` |
| 驱动 | `driver.path`、`driver.userwritable`、`driver.signed`、`driver.signaturestatus` |
| WMI | `wmi.name`、`wmi.query`、`wmi.consumer.type`、`wmi.destination` |
| 进程访问 | `target.pid`、`target.image`、`target.access` |
| 扩展字段 | `field.<name>` |

未知字段会被校验器拒绝，避免拼写错误导致规则永不命中。实现插件时可把自定义值放入 `TelemetryEvent.Fields`，在策略中用 `field.<name>` 引用。

## 3. 构造事件样本

样本文件支持数组，也支持带元数据的文档格式：

```json
{
  "schemaVersion": 1,
  "source": "lab-capture",
  "samples": [
    {
      "event": { "kind": "NetworkConnect", "destinationPort": 8443, "destinationIp": "192.168.127.100" },
      "process": { "pid": 4242, "imagePath": "C:\\Users\\Public\\np_rce.exe", "isUserWritable": true }
    }
  ]
}
```

至少准备一个应命中的正样本和一个不应命中的正常样本，用 `simulate` 查看命中字段。GUI 的“导出实时样本”会保留最近真实遥测，适合回归测试。

### 3.1 回归测试用例

回归测试把“样本 + 预期规则”固化为可重复验收用例。`strict: true` 时，出现任何未声明命中都会失败，适合正常样本的误报回归。

```json
{
  "schemaVersion": 1,
  "name": "示例回归测试",
  "strict": false,
  "cases": [
    {
      "name": "8443 命中",
      "expect": ["RESEARCH-C2-8443"],
      "event": { "kind": "NetworkConnect", "destinationPort": 8443 },
      "process": { "imagePath": "C:\\Users\\Public\\np_rce.exe" }
    }
  ]
}
```

`forbid` 用于声明不得命中的规则；`expect`、`forbid` 中出现策略包里不存在的规则 ID 会直接判失败。

## 4. 命令行闭环

```powershell
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- validate .\policy.json
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- simulate .\policy.json .\events.json
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- test .\policy.json .\tests.json
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- coverage --policy .\policy.json --markdown
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- install .\policy.json
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- list
dotnet run --project .\BaguetteAV.EDR.PolicyTool -- rollback research.example.c2
```

安装成功后会生成 `installed/<policy-id>/<version>/policy.json` 与 `meta.json`。服务热加载时重新校验 SHA256；手工修改安装目录中的策略会被拒绝。

## 5. 代码插件

当规则需要跨事件状态时，实现 `IEdrPlugin`：

```csharp
public sealed class MyPlugin : IEdrPlugin
{
    public string Id => "research.my-plugin";
    public string Name => "My research plugin";
    public string Version => "1.0.0";
    public IEnumerable<PolicyPack> GetPolicyPacks() => Array.Empty<PolicyPack>();
    public IEnumerable<DetectionRule> GetRules()
    {
        yield return new MyRule();
    }
}
```

插件 DLL 放到 `%ProgramData%\BaguetteAV\EDR\plugins`，执行 `trust-plugin` 写入 SHA256 后重载。未登记、哈希不匹配或加载异常只产生错误，不影响内置规则。

## 6. 防护边界

策略引擎的响应发生在遥测事件之后：可以告警、终止进程、隔离文件和阻断远端地址，但不是内核级前置拦截。已经完成的 LSTAR/MSR 写入、DKOM 全链表摘除和内核内存篡改，用户态 EDR 无法可靠恢复；必须在驱动加载前用 HVCI、WDAC、Microsoft 漏洞驱动阻止列表或 hypervisor 级监控拦截。把这一点写进策略说明和论文结论，避免把“检测到”夸大成“内核全覆盖”。
