# B-EDR 自定义防护策略包与信任链

## 1. 设计目标

普通杀软的自定义能力通常停留在开关、白名单和少量 HIPS 选项。B-EDR 把“新增一种防护能力”拆成可验证、可分发、可回滚的工程对象，目标是：

1. 研究人员可以把新样本的行为快速沉淀为策略，不需要改动主程序。
2. 策略交付物能证明“谁发布、改了什么、在哪些样本上验证过”。
3. 导入失败时不影响内置规则，导入成功后无需重启服务即可生效。
4. 对主动响应能力做风险分级，避免研究策略误伤系统。
5. 复杂逻辑通过受信任插件扩展，并保持插件与声明式策略的信任边界分离。

## 2. 两层导入模型

| 层级 | 文件 | 适用场景 | 信任与门禁 |
|---|---|---|---|
| 本机研究层 | `*.json` | 本机快速迭代、调试条件树 | 校验格式与复杂度；允许未签名 |
| 可分发交付层 | `*.bedrpack` | 论文复现、团队共享、答辩演示 | 发布者验签、逐文件哈希、回归门禁、风险分级 |

`.bedrpack` 是 ZIP 容器，但不是“可执行插件”。其中只允许声明式策略、回归用例、样本和说明文档；服务不会执行包内脚本。

### 2.1 包结构

```text
research.bedrpack
├── manifest.json      # 文件清单、策略 ID/版本、发布者、质量门禁
├── manifest.sig       # 对 manifest.json 原始字节的 ECDSA P-256 签名
├── policy.json        # 声明式策略
├── tests.json         # 正样本、负样本、expect/forbid/strict
├── fixtures.json      # 可选：离线演练样本
└── README.md          # 可选：研究说明、样本来源、误报边界
```

`manifest.json` 记录每个文件的 SHA256 与大小。签名只覆盖清单，清单再绑定全部文件，因此修改策略、测试或样本都会导致验签链失败。

## 3. 信任链

```text
管理员导入公钥
      │
      ▼
本机 trusted-publishers.json（ACL 仅 SYSTEM/Administrators）
      │  KeyId = SHA256(SubjectPublicKeyInfo)
      ▼
.bedrpack manifest.sig ── ECDSA P-256 ──► manifest.json
                                             │
                                             ├── policy.json  SHA256
                                             ├── tests.json   SHA256
                                             ├── fixtures     SHA256
                                             └── README       SHA256
```

关键属性：

- 发布者使用 P-256 ECDSA 密钥对；私钥留在研究机或受控构建环境。
- 服务只信任本机 `trusted-publishers.json` 中登记过的公钥。
- 未信任发布者默认拒绝安装；`verify-package --allow-untrusted` 仅用于结构检查。
- 信任清单缺失、损坏或超过限制时按“无信任发布者”处理，包被拒绝。
- 发布者信任的导入与撤销写入 `trust-audit.jsonl`，记录 KeyId、操作者、主机和时间；审计不可写时回滚本次信任变更。
- 策略数据目录由服务启动和导入前收紧 ACL；加固失败时禁用外部策略和插件。

这不是“供应商云查杀”信任链：研究机本地就是信任根，适合隔离实验室和可复现实验。

### 3.1 信任撤销与轮换

GUI 的“发布者信任”区域列出本机信任根，并允许逐个撤销；命令行等价命令为 `revoke-key <KeyId>`。撤销不会删除已安装策略或历史审计，但会让相关签名包在下次热加载时复验失败并退出活动策略集。这种失败是刻意设计：信任根变化必须立即影响可执行配置，不能等下一次重启。

策略列表以实际加载结果为准：活动版本复验失败时显示“加载被拒绝”和具体原因，并且不计入已启用规则数。

密钥轮换应先导入新公钥，再用新私钥发布提升过版本号的策略包，最后撤销旧发布者。不要用同一策略 ID/版本重新签名覆盖，否则会破坏不可变版本与实验结果的可追溯性。

## 4. 导入状态机

```text
采集遥测
  → 编写 JSON
  → 离线演练
  → 回归测试（正样本命中、负样本静默）
  → 覆盖率检查（每条启用规则至少一个正样本）
  → 签名打包
  → 本机信任发布者
  → 验签/哈希/解压边界检查
  → 暂存目录写入完整版本并复核包哈希
  → 切换不可变版本目录（旧目录临时备份）
  → 原子切换 active 指针
  → 任一步失败恢复旧目录并清理暂存
  → 热加载
  → 复验签名与回归
  → 实时命中/响应
  → 回滚或提升版本
```

任何一步失败都不会把策略标记为 active。安装后的版本目录包含 `policy.json`、`tests.json`、`manifest.json`、`manifest.sig`、`meta.json` 和原始 `package.bedrpack`，便于审计和复现。暂存目录位于策略仓库的 `.staging` 下，不会出现在已安装策略列表；成功提交后清理，失败时恢复被替换的旧版本目录。

## 5. 质量门禁

`.bedrpack` 默认执行以下门禁：

| 门禁 | 默认行为 | 目的 |
|---|---|---|
| JSON Schema/字段校验 | 拒绝未知字段、操作符、事件类型 | 防止拼写错误造成永久不命中 |
| 条件复杂度 | 深度 ≤ 10，节点 ≤ 256，规则 ≤ 512 | 限制正则和递归回溯成本 |
| 正则编译 | 单次匹配超时 100 ms | 防止灾难性回溯阻塞检测线程 |
| 正样本覆盖 | 每条启用规则至少出现一次 `expect` | 防止“装了但从未验证” |
| 严格负样本 | 回归集至少一个 `strict` 或全静默用例 | 约束误报 |
| 回归执行 | 全部用例必须通过 | 防止策略版本在引擎上失效 |
| 文件哈希 | 清单内每个文件必须匹配 | 防止交付后被替换 |
| 发布者验签 | 必须命中本机信任公钥 | 证明发布者身份 |
| ZIP 边界 | 8 MB 包、16 MB 展开、32 个文件 | 防止压缩炸弹和路径穿越 |
| 版本不可变 | 同 ID/版本内容不可改写 | 保证审计可追溯 |

可以使用 `--allow-uncovered` 或 `--allow-no-negative` 构建研究草稿，但默认答辩/交付包不建议关闭门禁。

## 6. 能力与风险分级

导入验收会从规则自动归纳能力标签：

- `file`、`driver`、`network`、`wmi`
- `process-access`、`remote-thread`
- `active-response`、`terminate-process`、`quarantine`、`network-block`、`contain`

风险级别按能力组合计算：

| 级别 | 触发条件 | 建议 |
|---|---|---|
| `DetectionOnly` | 只有告警类规则 | 先观察误报 |
| `HighVisibility` | 驱动、进程访问或远程线程 | 在隔离样本机验证 |
| `ActiveResponse` | 包含终止、隔离、阻断或 contain | 先使用 alert 版本，再逐步升级 |
| `KernelSensitive` | 驱动能力与 Critical 规则同时出现 | 必须配合负样本和回滚 |

策略中的 `response` 只是“请求动作”。最终是否终止、隔离或阻断仍受全局自动处置开关和受保护进程限制，策略不能绕过系统安全边界。

## 7. 失败关闭语义

以下情况会让外部策略不参与实时检测，并产生加载错误：

- 数据目录 ACL 无法收紧；
- 信任清单损坏或发布者不在清单；
- 发布者信任被撤销，导致已安装签名包复验失败；
- 包签名、文件哈希或大小不匹配；
- 回归测试失败或启用规则没有正样本；
- 已安装包在热加载时复验失败；
- 规则 ID 与内置规则或其他策略冲突。

内置规则和已通过校验的策略继续运行。界面会显示策略加载错误，避免出现“服务还活着，但防护已经悄悄失效”的假象。

## 8. 研究型扩展点

### L1 本地设置

监控开关、自动处置、IOC、端口和保留策略。适合演示和实验条件控制。

### L2 声明式策略包

进程、网络、文件、驱动、WMI、LSASS 访问、远程线程的复合条件。新增检测不需要重新编译主程序，热加载生效。

### L3 遥测样本与回归

把真实事件导出为样本，形成 `expect/forbid/strict` 用例、覆盖报告和误报基线。策略从“经验规则”变成可重复实验。

### L4 受信任插件

需要时间窗、跨事件状态机或专有解析器时，实现 `IEdrPlugin`。插件 DLL 必须登记 SHA256，默认拒绝加载；插件异常与内置规则隔离。插件运行在服务进程内，属于高信任代码，不能把“已签名策略包”的安全属性外推到插件。

## 9. 与消费级杀软的差异

| 维度 | 普通消费级 AV | B-EDR |
|---|---|---|
| 自定义入口 | 开关、白名单 | 声明式策略包 + 可信插件 |
| 规则验证 | 厂商内部 | 本地演练、回归、覆盖报告 |
| 交付证明 | 不透明云端 | 发布者签名、逐文件哈希、审计 |
| 版本管理 | 自动覆盖 | 不可变版本、active 指针、回滚 |
| 研究样本 | 通常不可导出 | 实时遥测导出为可复现样本 |
| 失败可见性 | 黑盒 | 加载错误、验签失败、测试失败均可见 |
| 内核马边界 | 容易被营销为“全拦截” | 明确用户态限制，要求 HVCI/WDAC/驱动拦截补齐 |

## 10. 复现命令

```powershell
$tool = ".\BaguetteAV.EDR.PolicyTool\bin\Release\net8.0-windows\bedr-policy.exe"

& $tool keygen --private .\lab-private.pem --public .\lab-public.pem
& $tool trust-key .\lab-public.pem --name "B-EDR Lab"

& $tool pack `
  --policy .\samples\policies\kernel-research.policy.json `
  --tests .\samples\policies\kernel-research.tests.json `
  --key .\lab-private.pem `
  --publisher "B-EDR Lab" `
  --out .\kernel-research.bedrpack

& $tool verify-package .\kernel-research.bedrpack
& $tool install-package .\kernel-research.bedrpack
& $tool list

# 从 publishers 输出取得 KeyId 后撤销，并验证策略包重新导入被拒绝
& $tool publishers
& $tool revoke-key <publisher-key-id>
```

GUI 中先点击“信任发布者”导入 `lab-public.pem`，再点击“导入策略包”选择 `.bedrpack`。导入成功后策略行会显示发布者、验签状态、回归通过数和风险级别。“发布者信任”区域可查看本机信任根并撤销发布者，用于演示密钥失陷后的失败关闭行为。

## 11. 研究边界

该框架能证明“策略交付链”和“用户态行为检测”可复现，但不能把用户态 EDR 宣称为内核级完整防护。已经完成的 LSTAR/MSR 写入、DKOM 全链表摘除和内核内存篡改，需要 HVCI、WDAC、Microsoft 漏洞驱动阻止列表、内核回调或 hypervisor 级监控配合。论文中应将本架构定位为“可扩展的端点检测与策略研究平台”，而不是“替代内核安全机制”。
